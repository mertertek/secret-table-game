### Supabase şeması — canlı yerel DB'de doğrulandı (`supabase start` + `psql`)

Migration'lar (`0001_schema`, `0002_functions`, `0003_realtime`) `supabase db
reset` ile temiz uygulandı. Doğrulanan davranışlar:

- `commit_move` atomik CAS: `ok` → aynı anahtar+özet `duplicate` → farklı özet
  `duplicate_digest_mismatch` → yanlış sürüm `version_conflict`; çatışmada durum
  değişmedi (revision 1'de kaldı).
- **RPC EXECUTE kilidi:** `authenticated`/`anon` `commit_move`/`join_room`/
  `create_room` çağıramıyor (`permission denied for function`). Yalnız
  `service_role`. (İlk sürümde eksikti — PUBLIC mirası; `revoke ... from public`
  ile düzeltildi ve yeniden test edildi.)
- **Tablo ayrıcalıkları:** `authenticated`/`anon` `game_states` /
  `processed_commands` / `player_sessions` seçemiyor/yazamıyor
  (`permission denied for table`). Doğrudan `update game_states` da reddediliyor.
- **RLS kapsamı:** `authenticated` yalnız kendi `room_members` satırını (mine=1,
  others=0) ve üyesi olduğu odayı (1) görüyor.
- `notify_room_revision` (`realtime.send`) `commit_move` içinde hatasız çalışıyor.

### API + canlı Supabase entegrasyonu (dev sunucusu + gerçek anon token)

`SUPABASE_URL`/`SUPABASE_SECRET_KEY` verilip dev sunucusu `SupabaseGateway` +
gerçek Supabase Auth token doğrulaması ile çalıştırıldı. GoTrue'dan alınan anon
JWT'lerle: `create_room` (`mode: supabase`) → 4× `join_room` → `start_game` →
`view` (p1 `fascist`, `fascists_know_each_other` bilgisiyle; p2 `hitler`, yalnız
kendi rolü; public sızıntı yok) → `command` (ack) → **idempotent replay** (aynı
revision, ikinci etki yok).
